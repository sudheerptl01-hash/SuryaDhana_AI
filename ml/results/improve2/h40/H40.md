## 1. Definitions (written before any result of this stream existed)

### Dataset `ml/data_10y_h40/`

- **Rows and features:** exactly the rows (2,226,504) and the 52 features of `ml/data_10y/`, same order. Nothing is re-derived for the features.
- **Labels, 40-day versions under the 20-day column names** (so `ml/improve/ab.py` runs unchanged; `manifest.json` says so in `label_horizon_sessions: 40` and `label_columns_renamed_warning`):
  - `y_raw_20d` := open[t+41] / open[t+1] − 1, on the ticker's own rows of `equity_features` (read from `ml/results/improve/cache/features_prices_export_10y.parquet`; split/bonus-adjusted opens, which is what the 10-year build used for its 20-day labels);
  - `y_excess_20d` := `y_raw_20d` minus the per-date median of `y_raw_20d` over that date's dataset rows (the universe rows; NaN skipped; clean and unclean rows both enter, exactly as `ml/data.py`);
  - `y_rank_20d` := per-date percentile rank of `y_excess_20d`; `label_beat_mkt_20d` := 1 if `y_excess_20d` > 0, 0 if ≤ 0, NaN where `y_excess_20d` is NaN;
  - `y_clean_20d` := `y_raw_20d` present (the ticker has rows t+1 and t+41 in its own history) AND open[t+1] > 0 AND open[t+41] > 0 AND (date[t+41] − date[t+1]) ≤ 88 calendar days AND max |ret_1d| over the ticker's rows t+1..t+41 ≤ 22%, where ret_1d = close / previous row's close − 1 on adjusted closes (the dataset's `ret_1d`);
  - `exit_date` := the date of the ticker's row t+41.
- **Code-path proof:** the same functions run with horizon 20 (span 45 days, window 21 rows) must reproduce `ml/data_10y`'s `y_raw_20d`, `y_excess_20d`, `y_rank_20d`, `label_beat_mkt_20d`, `y_clean_20d`, `exit_date` and `ret_1d` exactly (bitwise, NaN positions included), and the split rule with a 22-session embargo must reproduce `ml/data_10y/splits.json`. The build stops if either check fails.
- **Splits:** the same 103 fold test windows (2018-01..2026-07) and the holdout window starting 2026-08-03; `train_end` = the session 42 sessions before `test_start` (embargo 42), for the holdout likewise; `test_end` = min(month end, last 40-day-labelled session), the `ml/data.py` rule. The harness's exit-date purge then drops training rows whose 40-day exit is on or after `test_start`.

### Books (`python3 -m ml.improve.h40 books`)

- **Base panel (identical for both scorers):** dataset rows in the 40-day test windows whose 40-day label is present and 40-day clean, **and** whose 20-day label is present and 20-day clean (deviation 3).
- **Blocks:** `ml/books/engine.build_blocks_h` with H = 40: entry at the open of session t+1, marks open-to-open on the session grid of `features_prices_export_10y` (from 2017-10-02, as the ten-year A/B books), exit at the open of t+41, **no label pin**; then phase-1 P2's 40-session screen (`ml/books/construct.py` `H_LONG`): a base row is dropped when its ticker's |ret_1d| exceeds 22% on grid sessions t+1..t+41 (`ml/books/data.forward_absret_max`, window 41) or when the t+41 session does not exist.
- **Scores:** each scorer's out-of-sample predictions joined one-to-one on (date, ticker) with the label check of `ml/books/data.load_scores` (the 20-day control against its 20-day label, the 40-day model against its 40-day label); neutralised per signal date on the base rows with `ml/books/engine.neutralise(kind="vol+size")` (OLS of the score's percentile rank on the ranks of `atr_pct` and `log_turnover`, residual re-ranked).
- **Baskets:** `top_decile` (full universe) and `liq_top_decile` (liquid tercile, `cs_rank_turnover` ≥ 0.67) via `members_simple`; equal weight; 40 overlapping tranches.
- **Benchmarks:** the engine's equal-weight universe and equal-weight liquid tercile with the same H = 40 and the same blocks.
- **Costs:** 10 / 20 / 40 bps per side netted against the tranche replaced, 20 bps without netting, and the P2 name-level model; break-even flat cost per side from `breakeven_long`.
- **Summary:** `ml/books/construct.summarize`; DSR = `ml/strategy_backtest.dsr_block` on the combined daily net (20 bps) skill series, N = 261, V[SR] = 0.00387.
- **Scorers:** `control20` = `ml/results/improve/ab/10y/preds/control__beat_mkt_20d.parquet` (the 20-day control, run now); `h40` = `ml/results/improve/ab/10y_h40/preds/control__beat_mkt_20d.parquet` (the 40-day model; the file name keeps the harness's 20-day naming, the label inside is the 40-day one).

### Pass mark (plan Q5, unchanged)

The 40-day model's neutral full-universe 40-session book (`h40|vol+size|top_decile|H40`) beats the 20-day control's (`control20|vol+size|top_decile|H40`):

1. **paired monthly difference:** for every signal month, (40-day model's mean net 20 bps tranche excess over the EW universe) − (control's), both books on the same blocks and the same benchmark; mean over months with a bootstrap 95% CI, months resampled with replacement, B = 1000, seed 108. The binding reading is this month-resampled CI with its lower bound > 0. A 3-month circular moving-block bootstrap (B = 1000, seed 108) is reported beside it; the JSON also gives the strict reading (both CIs above zero);
2. **and** the 40-day model's flat break-even cost per side is higher than the control's (a book whose gross excess is ≤ 0 has no positive break-even and counts as 0 bps).

Both must hold. The comparison code is exercised on the control's book against itself (difference exactly 0, verdict FAIL) before it is used.

The AUC of the 40-day model is reported for description only: it is measured on a different label from the control's and is not part of the pass mark.

## 2. Deviations and readings (fixed before running)

1. **Holdout test window ends earlier.** A 40-day label needs 41 forward sessions; the data end on 2026-10-16, so the last 40-day-labelled session is in mid-August 2026. By the `ml/data.py` rule (`test_end` = min(window end, last labelled session)) the holdout window is 2026-08-03..that session instead of ..2026-09-16; folds 2018-01..2026-07 are complete.
2. **5-session labels not carried.** `fwd_ret_5d` and `label_up_5d` (the 5-session secondary labels) have no 40-day version and are not used by the harness or the books; they are left out of `ml/data_10y_h40` so the dataset carries one horizon only.
3. **Common base panel.** The 20-day control has no score on rows that are 40-day clean but not 20-day clean (for example a 46-day gap inside the first 21 rows). Both scorers' books are therefore built on the intersection of the two clean masks, so they rank the same names on the same dates against the same benchmark; the row count removed is reported in `books_*.json` (`base_panel`).
4. **"All 41 sessions present" read as the ml/data.py rule.** It is read as "the ticker has the rows t+1..t+41 in its own history" with the 88-day span cap guarding suspensions, the way the 20-day label reads "all 21". A stricter reading (the ticker's rows t+1..t+41 are the 41 consecutive market sessions) would make the 20-day reproduction fail; the number of 40-day-clean rows with a missing market session inside the window is reported in `build.json` so the choice can be judged.
5. **P2's 40-session screen is applied on top of the dataset's 40-day clean mask,** as the brief asks. It is implied by that mask (same returns, a window of rows that covers at least the same sessions), so it should remove no rows; the count is reported.
6. **Months compared.** All signal months of the 40-session books (2018-01..2026-08, CV and holdout together), as P2's B2 compared books; the CV-only months (signal months before 2026-08) are reported too.
7. **First fold.** With a 42-session embargo the 2018-01 fold trains on about 21 sessions (the dataset starts 2017-10-03), against 41 for the 20-day dataset. This is what the plan's split rule gives; no fold is dropped.
8. **Harness file names.** `ml/improve/ab.py` writes `control__beat_mkt_20d.json` / `.parquet` under `ml/results/improve/ab/10y_h40/`; the names say 20d because the harness is unchanged. Everything in that folder is on the 40-day label.
