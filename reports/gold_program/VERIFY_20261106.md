## 4 · Defects found by this verification and fixed today

1. **Accuracy-log dual-write refused since it shipped.** ui-api posted `{"row": row}`; data-service's `/jobs/gold-log` reads the
   row's fields at the top level, so every dual-write in the logs returned 422 and `gold_preopen_log` (the DuckDB copy) stopped at the
   one-off migration (30 Oct) while `log.json` kept growing; DATA health read it RED. Fix: ui-api posts the row itself
   (`routers/gold_preopen.py`), and a new test runs data-service's real handler on the exact body ui-api sends (the old envelope
   is the negative control: 422). Re-synced from `log.json`: 10 days through Fri 6 Nov (fair ₹1,42,620 vs open ₹1,42,530, −₹90).
2. **COT freshness budget read amber every Friday.** CFTC publishes Tuesday's positions on Friday 15:30 ET (Sat ≈ 02:00 IST), so
   the newest stored report is 10–11 days old each Friday by design. Budget 9 → 11 days (`data_health/catalog.py`, the controller's
   `GOLD_MAX_AGE_DAYS`); a late (US-holiday) release still reads amber.
3. **Swiss customs gold exports to India stored nothing.** The group had never run (monthly, 22nd; the program went live 4 Nov).
   Its first run streamed the 692 MB BAZG file and matched 0 rows: the real header lists `Country_isoAlpha2` before `Country_txt`
   and `Supplementary_quantity` before `Quantity_kg`, and column detection took the first header match. Fixed (keys in priority
   order; a fixture with the real header verbatim and negative controls); re-run: **177 months, Jan 2012 → Sep 2026** (Sep 2026
   3,052 kg). Header layout recorded in `SOURCES.md` E19 and the generated dictionary.

DATA health after the fixes: 66 green · 1 amber (`news_track_record`, not gold: the nightly 19:45 run clears it) · 0 red.
