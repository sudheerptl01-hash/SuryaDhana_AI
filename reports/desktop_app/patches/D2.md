## 2. Contract v1 amendment: window dragging for the terminal origin (PM decision)

**What.** The remote capability (`desktop/src-tauri/capabilities-runtime/terminal-remote.json`) grants the 9 `shell_*`
commands **plus** two core window permissions:

- `core:window:allow-start-dragging` → `plugin:window|start_dragging`
- `core:window:allow-internal-toggle-maximize` → `plugin:window|internal_toggle_maximize`

**Why.** The window uses the overlay title bar with a hidden title (AC-7). That leaves no native draggable title bar,
so the only way to move a window is D4's `TitleStrip`, whose non-interactive elements carry `data-tauri-drag-region`.
Tauri's built-in drag script turns a mousedown on such an element into `plugin:window|start_dragging`, and a
double-click into `internal_toggle_maximize` (the standard macOS "double-click the title bar to zoom"). Without these
two permissions, terminal windows cannot be dragged at all, and every double-click logs an ACL error in the console,
which counts against AC-3.

**Risk.** Both commands act only on the calling window: move it, or zoom/unzoom it. Neither reads or writes data, and
neither touches processes or files. This covers a port squatter on :8010 too.

**If approved.** T's guard test needs one constant. File `tests/integration/test_desktop_contract.py` (owner T). The

**If rejected.** Drop the two `core:window:*` lines from `terminal-remote.json` and rebuild. Windows can then be moved
only by the native title-bar band, which with the Overlay style is effectively none. Better: D4 removes
`data-tauri-drag-region` from `TitleStrip`, and D2 switches the window to `TitleBarStyle::Visible` (a standard
title bar).
