## services/ui-api/main.py

**Why.** This adds `GET /version`, `GET /ready` and `GET /live`; main.py has only `/health`, which I
checked. It also mounts the static terminal UI from `ui/dist/current`, or `$UI_DIST_DIR` if that is set.

`mount_static_ui` installs the UI as the router's **not-found fallback** (`app.router.default`), not
as a route or a `Mount("/")`, so a request reaches it only when no route matches. It therefore never
shadows `/api/*`, `/health`, `/docs` or the other built-in paths, and it doesn't shadow routes added later
either, such as D3's prefs router. It keeps 405 and `redirect_slashes` working and leaves OpenAPI
unchanged. Unknown `/api/*` paths still get the JSON envelope 404 from the handler above. Nothing else in
main.py changes. A missing build never fails startup: `/` serves a 503 "build missing" page and the API
keeps working.

**Order with D3.** Call order does not matter functionally, because the UI is the fallback. Still, keep
this block as the last statements of the file, after D3's `include_router` for prefs.
`test_static_ui.py::test_main_py_wiring_when_applied` enforces that `mount_static_ui` comes after every
`include_router`. If D3's block is also anchored on the `/health` function, apply D3's first, then this
one with the OLD text below. The OLD text is the `/health` function, which stays intact.

## start-local.sh

**Behaviour after the patch:**
- `CORE_SERVICES` is `data-service ui-api master-controller`.
- `start` (or no argument) starts the 3 core services and prints `Terminal: http://127.0.0.1:8010` with
  the current UI release id.
- `start frontend` and `restart frontend` are unchanged: dev by default, `UI_MODE=prod` for the old Next
  build. `frontend` stays in `ALL_SERVICES`, so `stop`, `status` and `logs frontend` still cover it.
- Starting ui-api warns when `ui/dist/current` has no release.
- `build-ui [args]` runs `scripts/build_ui.sh`.
- `status` shows `frontend` as **off (optional dev UI)** instead of red `down`, and adds a `ui-release` row.
- Paused markers, `start legacy`, `UI_API_RELOAD`, the stop order and graceful stop are untouched.

One difference: a full `restart` stops `frontend` along with everything else, as before, but no longer
starts it again, because it is not core. That is the intent.

### P6: warn when ui-api starts without a UI release

OLD:
```bash
start_one() {
  local name=$1 spec dir app port extra
  spec=$(svc_spec "$name"); IFS='|' read -r dir app port extra <<< "$spec"
```

NEW:
```bash
# The UI release ui-api serves (scripts/build_ui.sh swaps ui/dist/current atomically). Prints its id.
ui_release_id() {
  [ -f "$UI_RELEASE_DIR/index.html" ] || return 1
  basename "$(cd "$UI_RELEASE_DIR" 2> /dev/null && pwd -P)"
}

warn_if_no_ui_release() {
  if ! ui_release_id > /dev/null; then
    echo -e "${YELLOW}!${NC} No UI release at ui/dist/current: the terminal at http://127.0.0.1:8010 shows a"
    echo -e "  'UI build not found' page until one exists (the API works). Build one: ./start-local.sh build-ui"
  fi
}

start_one() {
  local name=$1 spec dir app port extra
  spec=$(svc_spec "$name"); IFS='|' read -r dir app port extra <<< "$spec"
  if [ "$name" = "ui-api" ]; then warn_if_no_ui_release; fi
```
