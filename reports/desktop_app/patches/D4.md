# D4 patch blocks (desktop UX + performance)

Apply with uniqueness-asserted replacement: each OLD block occurs exactly once in its file today (checked
24 Oct 2026 against the working tree). Five groups; apply P5 together with P11, the rest are independent:

- **layout (P1–P6)**: the desktop title strip and the connection banner publish their height as
  `--shell-top` on `<html>` (PlatformShell). These six one-line hooks make the app's own fixed/sticky chrome
  sit below it. In a browser with no banner `var(--shell-top, 0px)` is `0px`, so rendering there is
  identical to today. No page logic changes.
- **perf (P7–P8)**: evidence-backed, pure-performance (`perf_baseline.md`, before/after on scratch builds).
  The components, props and API calls are the same; only *when* a tab's module is resolved changes.
- **bundle (P9a–P9e)**: pure-performance. Three string constants move to an import-free module so the
  eager CommandBar stops pulling three whole tab components into first-load JS. Same values, same exports.
- **fonts (P10)**: the last Google Fonts request in a mounted component (ALFA tab) goes; the family is
  self-hosted with the same weights, so nothing visible changes.
- **fix (P11)**: a latent styling bug found while verifying P5 (toasts invisible under the header).
  One added Tailwind content glob; additive CSS only.

Evidence for every perf/bundle/fonts block: `reports/desktop_app/perf_baseline.md` (section named in each
block). The scratch builds that produced it applied exactly these blocks with this same script.

No patch is needed to open the command bar: `{type:'command-bar'}` dispatches the `suryadhana:command`
window event that `CommandBar.tsx` already listens to.

## P7 · `ui/app/page.tsx` · perf

PERF (evidence: reports/desktop_app/perf_baseline.md §4). Every first visit to a lazy tab paid a ~300 ms floor: the dynamic() boundary suspends, shows TabSkeleton, and React 19 then holds the reveal until 300 ms after the fallback (FALLBACK_THROTTLE_MS: `globalMostRecentFallbackTime + 300 - now()` in react-dom) even when the chunk arrived in ~10 ms. Fix: remember the resolved module; a tab whose module is already resolved renders it directly (no Suspense, no skeleton, no throttle). The component is chosen once per mount (useState initializer), so a mounted tab never swaps component type: no remount, no state loss. Same components, same props, same data calls. Measured with P8 (§3–§4): UI-ready p50 311 → 21 ms (Chromium), 315 → 30 ms (WebKit); p95 326 → 45 / 379 → 107 ms; each page's first API request now starts ~12 ms after the switch instead of ~309 ms. One page gets slower: EQS in Chromium +109 ms, because its 1,496-row table render (~0.4 s) is no longer hidden inside the throttle window (perf_baseline.md §8; the fix there is windowing in StockTable, not this block).

OLD:
```tsx
const lazyTab = (load: () => Promise<React.ComponentType<any>>) =>
  dynamic(load, { loading: () => <TabSkeleton />, ssr: false })
```
NEW:
```tsx
// Perf (desktop program D4, reports/desktop_app/perf_baseline.md): a suspending dynamic() boundary shows the
// skeleton and React then holds the reveal for its 300 ms fallback throttle, even for a 10 ms chunk. So each
// tab remembers its resolved module and, once resolved (first visit, or the idle warm-up in HomeContent),
// renders it directly: no Suspense, no skeleton, no 300 ms floor. Chosen once per mount (no remount, no state loss).
const TAB_WARMERS: Array<() => Promise<unknown>> = []
const lazyTab = (load: () => Promise<React.ComponentType<any>>) => {
  let resolved: React.ComponentType<any> | null = null
  const warm = () => load().then(c => { resolved = c; return c })
  TAB_WARMERS.push(warm)
  const Lazy = dynamic(warm, { loading: () => <TabSkeleton />, ssr: false })
  const Tab = (props: any) => {
    const [C] = useState<React.ComponentType<any>>(() => resolved ?? Lazy)
    return <C {...props} />
  }
  return Tab
}
```

## P8 · `ui/app/page.tsx` · perf

PERF (with P7): warm the lazy tab modules one by one in idle time, starting 3 s after the terminal mounted, so even the FIRST visit of a tab renders without the skeleton. Skipped with Save-Data. Errors are swallowed: a tab that failed to warm simply loads on first visit as today. Cost (perf_baseline.md §4): 42 chunks, 239 kB gz, once per window (hashed chunks are immutable, so later windows hit the cache), +0.25 MB JS heap, no long task and no event-loop lag over 100 ms.

OLD:
```tsx
  useEffect(() => { loadDashboard() }, [loadDashboard, retryCount])

```
NEW:
```tsx
  useEffect(() => { loadDashboard() }, [loadDashboard, retryCount])

  // Perf (D4): warm every lazy tab module in idle time so first visits skip the skeleton (see lazyTab above)
  useEffect(() => {
    if ((navigator as Navigator & { connection?: { saveData?: boolean } }).connection?.saveData) return
    let cancelled = false
    const w = window as Window & { requestIdleCallback?: (cb: () => void, o?: { timeout: number }) => number }
    const idle = (cb: () => void) => (w.requestIdleCallback ? w.requestIdleCallback(cb, { timeout: 2000 }) : setTimeout(cb, 120))
    const next = (i: number) => {
      if (cancelled || i >= TAB_WARMERS.length) return
      idle(() => { if (!cancelled) TAB_WARMERS[i]().catch(() => undefined).finally(() => next(i + 1)) })
    }
    const start = setTimeout(() => next(0), 3000)
    return () => { cancelled = true; clearTimeout(start) }
  }, [])

```

## P11 · `ui/tailwind.config.ts` · fix

LATENT BUG found while verifying P5 (evidence: perf_baseline.md §9). Tailwind's `content` globs scan only app/ and components/, so the utilities used ONLY in context/ToastContext.tsx are never generated: 17 of its 44 classes are missing from the built CSS (z-[9999], right-4, pointer-events-auto, bg-{amber,rose,emerald,indigo}-950/90, border-*-600/60, opacity-0/100, translate-x-4, transition-opacity, break-words, hover:opacity-100). Every toast today renders with a transparent background, at the LEFT edge, with z-index auto, i.e. underneath the sticky header (measured in WebKit and Chromium: rect left 0, painted below the header). Scanning context/ makes Tailwind generate exactly those rules; the change is additive (new rules only for class names that appear in context/), so nothing else changes.

OLD:
```tsx
    './components/**/*.{js,ts,jsx,tsx,mdx}',
  ],
```
NEW:
```tsx
    './components/**/*.{js,ts,jsx,tsx,mdx}',
    './context/**/*.{js,ts,jsx,tsx,mdx}',
  ],
```
