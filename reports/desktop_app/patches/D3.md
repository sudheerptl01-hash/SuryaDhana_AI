# D3 patch blocks (platform bridge + prefs)

Every block below is an exact `old` → `new` replacement. Each `old` text was checked to occur **exactly once** in the
file as of 24 Oct, about 11:45 IST. **Re-checked after the reboots, about 15:50 IST**: every shared-file `old` text
still occurs exactly once, and every section-2 `new` text is present once in the working tree.

Two groups:

- **Shared files** (section 1, which the PM applies): one block is required (main.py); three are recommended
  (.gitignore, conftest.py, AppContext.tsx).
- **D3-owned call sites** (section 2, already applied in the working tree): recorded so the PM can review them. These
  files are untracked in git, so `git diff` cannot show the change.

### 1d. RECOMMENDED (optional; UX, not logic): `ui/context/AppContext.tsx`, adopt a watchlist synced from another window

Why: AppContext reads the watchlist from localStorage once, on mount. When a second window (or the browser) changes it,
the prefs sync writes the new value into localStorage and dispatches `suryadhana:prefs-changed`. AppContext ignores
that event, so this window keeps showing its old list. Worse, its next own edit would re-upload the stale list plus the
edit.

This is the same as with two browser tabs today, because AppContext has never listened to `storage`. So it is a
pre-existing limitation, not a regression. The patch fixes server-applied changes only: same-origin multi-window (⌘N)
needed the native `storage` listener added in the 25 Oct fix round (C3-02, `ui/lib/prefs/useExternalChange.ts`). The re-set value equals
localStorage, so the persist effect's `setItem` is a no-op for the sync (an unchanged value is never uploaded).

```text
--- old
    watchlistHydratedRef.current = true
  }, [])

+++ new
    watchlistHydratedRef.current = true
  }, [])

  // Synced from another window / the browser (lib/prefs/sync.ts applied a newer server value): adopt it.
  useEffect(() => {
    const onPrefs = (e: Event) => {
      const keys = (e as CustomEvent<{ keys?: string[] }>).detail?.keys
      if (!keys || !keys.includes(WATCHLIST_KEY)) return
      try {
        const parsed = JSON.parse(window.localStorage.getItem(WATCHLIST_KEY) || '[]')
        if (Array.isArray(parsed)) setWatchlist(parsed.filter((t): t is string => typeof t === 'string'))
      } catch { /* ignore corrupt/blocked storage */ }
    }
    window.addEventListener('suryadhana:prefs-changed', onPrefs)
    return () => window.removeEventListener('suryadhana:prefs-changed', onPrefs)
  }, [])

```

Context: the `old` text is the end of the "Hydrate once on mount" effect, which is followed by a blank line and then the
persist effect. `WATCHLIST_KEY` is already defined above it, and `setWatchlist` is in scope.
